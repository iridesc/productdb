# 提案：重构生产订单流程

## 动机

当前生产订单模块存在以下问题：

1. **状态机不完整**：代码跳过了草稿（draft）状态，创建即为待生产（pending），导致运营人员无法在发布前预览 BOM 物料需求并确认库存。
2. **业务流程不匹配**：实际业务中，运营人员需要先创建草稿，检查物料库存是否充足，不足时去采购、补充库存，再发布让工人生产。当前代码不支持此流程。
3. **成品入库缺失**：生产完成时仅设置了 `completed_quantity`，未将成品入库，导致库存账面亏损。
4. **无角色权限**：所有认证用户可执行任何操作，不支持运营/工人的分工协作。
5. **并发安全问题**：订单号生成逻辑（`count() + 1`）在并发场景下可能产生重复。

## 目标

重构生产订单模块，使其：

- 支持完整的 5 状态生命周期：草稿 → 待生产 → 生产中 → 已完成（+ 已取消）
- 发布时自动校验 BOM 物料库存并扣减
- 完成时自动将成品入库并生成库存流水
- 实现多角色权限系统（admin / operator / worker / sales / shipping）
- 订单号生成改为并发安全方案
- 前端按角色过滤视图，区分运营和工人的操作界面

## 非目标

- 不引入预占库存机制（发布时直接实扣）
- 不引入工序/排产管理
- 不改变成本核算精度（仍按 BOM 理论成本）
- 不重构销售订单模块（后续单独处理）

## 范围

### 后端
- 数据模型：`ProductionOrder` 状态枚举、`UserRole` 多对多关联
- API：新增 `publish`、`start`、`cancel` 端点，修改 `create`、`complete` 逻辑
- 权限：`require_roles` dependency

### 前端
- 生产订单列表/详情按角色过滤
- 草稿创建、编辑、删除界面
- 发布、开工、报工操作按钮

### 不受影响
- 物料管理、BOM 管理、客户管理
- 销售订单模块
- 库存管理基础功能
