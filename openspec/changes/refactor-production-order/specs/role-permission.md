# 角色权限系统

## 概述

系统应当支持多角色权限管理。一个用户可同时拥有多个角色，权限取所有角色的并集。管理员角色拥有所有权限。

## 角色定义

| 角色编码 | 角色名称 | 说明 |
|----------|----------|------|
| `admin` | 管理员 | 拥有系统所有权限 |
| `operator` | 运营 | 负责物料管理、库存调整、生产订单的创建和发布 |
| `worker` | 工人 | 负责领取生产订单、开工、报工 |
| `sales` | 销售 | 负责销售订单相关操作（本变更暂不涉及） |
| `shipping` | 发货 | 负责发货相关操作（本变更暂不涉及） |

## 数据模型

### UserRole（用户角色关联表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| user_id | UUID | 用户ID（FK → users.id） |
| role_code | String(20) | 角色编码（FK → roles.code） |
| created_at | DateTime | 创建时间 |

### Role（角色定义表）

| 字段 | 类型 | 说明 |
|------|------|------|
| code | String(20) | 角色编码（主键） |
| name | String(50) | 角色名称 |
| description | String(200) | 角色描述 |

### User 模型变更

User 模型应当新增 `roles` relationship，指向 UserRole。

## 初始化规则

1. 系统启动时应当自动创建 5 个角色（如不存在）。
2. 现有用户应当自动被分配 `admin` 角色（保持向后兼容）。
3. 新注册用户默认无角色，需要管理员手动分配。

## 生产订单权限矩阵

| 操作 | operator | worker | admin |
|------|----------|--------|-------|
| 查看生产订单列表 | ✅ 全部 | ⚠️ 仅 pending + in_production | ✅ 全部 |
| 查看生产订单详情 | ✅ | ✅（仅可看状态下） | ✅ |
| 创建生产订单 | ✅ | ❌ | ✅ |
| 编辑草稿订单 | ✅ | ❌ | ✅ |
| 删除草稿订单 | ✅ | ❌ | ✅ |
| 发布订单 | ✅ | ❌ | ✅ |
| 开工 | ❌ | ✅ | ✅ |
| 报工完成 | ❌ | ✅ | ✅ |
| 取消待生产订单 | ✅ | ❌ | ✅ |

## 权限检查实现

权限检查应当使用 FastAPI dependency 方式实现：

```python
require_roles("operator", "admin")   # 至少拥有其中一个角色
require_roles("worker", "admin")     # 同上
```

`admin` 角色自动通过所有 `require_roles` 检查。

## 前端行为

- 前端应当根据当前用户的角色显示或隐藏操作按钮。
- 纯工人角色用户的生产订单列表应当仅展示 `pending` 和 `in_production` 状态的订单。
- 运营角色用户应当看到所有状态的订单和所有操作入口。
- 同时拥有 operator + worker 角色的用户应当拥有两者的所有权限。
